# ASTROTOPIA · UNITED EXPLORERS

Phaser 3 + TypeScript + Vite 기반 탐험 게임에 **실제 서버가 판정하는 비공개 2–4인 협동 개발 모드**를 추가했습니다. 화면의 다른 탐험가는 독립 WebSocket 접속자입니다. 1–9단계 싱글플레이는 유지합니다.

9단계 완료 커밋: `650e6f1`. 당시 기록은 `docs/phase9-guide.md`, `docs/phase9-verification.md`에 보존했습니다. 요청 원문은 `docs/phase-10-brief.md`, 최종 검증 결과는 `docs/verification.md`입니다.

## 실행

Node.js **24.14 이상**이 필요합니다. 서버는 Node 내장 SQLite를 사용합니다.

```powershell
npm ci
Copy-Item .env.example .env
```

서로 다른 터미널에서 실행합니다.

```powershell
npm run dev:server
```

```powershell
npm run dev:client
```

클라이언트: `http://127.0.0.1:5180` / 서버 상태: `http://127.0.0.1:5190/health`.

1. 타이틀 → **협동 탐험** → 호출명 입력 → 개발용 게스트로 시작.
2. 월드 생성 → **월드 L** → 초대 코드 또는 초대 링크 복사.
3. 독립 브라우저 프로필이나 시크릿 창에서 다른 호출명으로 접속 → 초대 코드 입력.
4. **파티 P**에서 파티 구성. 월드 멤버십과 파티는 별도입니다.

게스트 세션은 8시간 유지됩니다. 영구 계정 복구·이메일 로그인은 제공하지 않습니다. 로그아웃이나 만료 후 기존 게스트 계정을 복구할 수 없으며, 새 게스트에게 월드 소유권이 자동 이전되지 않습니다. 싱글플레이는 서버 없이 사용할 수 있습니다.

## 저장과 서버 권한

- 싱글플레이: 기존 `astrotopia.save.v1` 키의 v9 저장, 이전 버전 변환·백업 유지.
- 온라인: `COOP_DATABASE`의 SQLite. 로컬 캐릭터·장비·화폐를 가져오지 않습니다.
- 온라인 세션·미응답 요청은 `astrotopia.online.*` 별도 브라우저 키. 요청 ID를 재접속 후에도 유지합니다.
- 서버 판정: HP/EP, 이동·충돌, 공격 방향·거리·쿨다운, 적·경험치·보상, 자원·화폐·건설·거래·연구·항해.
- 자원 변경과 요청 처리 기록을 같은 DB 트랜잭션에 저장합니다. 같은 요청 재전송은 기존 결과를 반환합니다.
- 개인 가방·개인 보관함·공동 창고·관리자 보관함 분리. 보상이 가방 한도를 넘으면 개인 보류 보상으로 남고 EDEN에서 회수할 수 있습니다.
- OWNER / ADMIN / BUILDER / OPERATOR / MEMBER / VISITOR. 신규 멤버는 MEMBER입니다. 공동 출금·건설은 별도 권한이 필요합니다. 소유자는 UI에서 역할을 바꾸며, 프로토콜은 작업별 권한 재정의도 지원합니다.
- 거래는 요청 → 수락 → 자원 제안 → 양쪽 준비 → 양쪽 최종 승인 순서입니다. 제안 자원은 서버가 보관하며, 변경 시 승인 초기화, 취소·접속 종료·서버 재시작 시 반환합니다.

## 전투와 성장

기존 이동 물리·지형·적 데이터·무기 정의를 공유합니다. 6개 클래스에 온라인용 Q/E/R/T 기술을 연결했습니다. AEGIS FIELD / GUARDIAN LINK / FORTRESS, SUPPORT DRONE / REPAIR FIELD, GENESIS BLOOM / ADAPTIVE FIELD 등의 대상·거리·파티·EP·쿨다운을 서버가 확인합니다. 방어 효과는 배율을 누적하지 않습니다.

실제 피해·유효 지원 참여자에게 개인 보상을 지급합니다. 접속만 한 캐릭터는 제외합니다. 보스 HP는 시작 인원에 따라 1 / 1.6 / 2.2 / 2.8배로 고정합니다. 다운 25초, 같은 파티원의 110px 이내 3초 소생, 30% HP 회복, 거리 이탈·피격 시 중단, 원정당 소생 2회 제한을 적용했습니다.

온라인 장비는 개인 재료·크레딧으로 무기와 환경 슈트를 7단계까지 제작하는 별도 성장입니다. 싱글플레이의 모든 장비 옵션·무기·스킬 트리를 온라인 가방으로 옮긴 것은 아닙니다. 기존 싱글플레이 전투 시스템은 유지합니다.

## 공동 개척과 경제

기존 `ColonySystem`, 생산 대기열, 연구, `CivilizationSystem`을 서버에서 실행합니다. 기지 셔틀로 건설 구역에 이동할 수 있습니다. 40px 격자·충돌·스토리 시설 보호·기술·재료를 검사하며 같은 위치의 동시 건설은 하나만 성공합니다. 전력·물류·출력 창고 조건이 충족되어야 생산됩니다.

자원 레시피·기술 연구·MK1/2 화물선·항로·시장·정거장 단계·ODYSSEY·국소 복원을 권한 검사와 연결했습니다. 행성별 창고와 공동 자금은 분리합니다. 개인 결정 기여로 공동 연구 포인트를 얻을 수 있습니다. 같은 연구의 중복 시작은 차단합니다. 비접속 경제는 기존 단일 시계의 최대 4시간 처리이며 월드 재개당 한 번 적용합니다.

## 행성과 원정

- 7개 행성의 기존 지역 사용. 이전 행성 보스 조사로 다음 행성 해금. 온라인 TITAN 조사는 기초 고대 분석·개척 연구의 선행 기록을 제공합니다.
- 다른 행성·지역·인스턴스의 캐릭터·적을 전투 스냅샷에서 제외합니다. 지역 출입구 근처에서 지역을 이동합니다.
- 대장 제안 → 각자 탑승·준비 → 대장 출발. 공동 창고의 출발 행성 현지 연료 자원을 한 번 사용합니다. 탑승하지 않은 멤버는 이동하지 않습니다.
- 자원 납품·생명체 분석·실종 탐험가 구조·자동 생산·유적 조사 5종 임무. 실제 기여자만 보상받습니다.
- CRYSTAL DEPTHS / HELIOS REACTOR / ABYSSAL ARCHIVE / NEXUS VAULT: 기존 지형을 복제한 파티별 전투 인스턴스입니다. 새 맵 아트나 싱글플레이의 모든 퍼즐을 재현한 던전은 아닙니다.
- STELLAR COLOSSUS: 엔딩 이후 Lv.90+ 원정. 레이저·충격파·중력 균열·과부하 4단계, 지원 드론, EP 보조, 2/4명에 맞춘 서로 다른 보조 장치·코어 노출·첫 보상 기록.
- 탐사단 이름·배너·목표·평판·보스 기록 저장.
- 엔딩은 GENESIS 실제 참여자의 과반수 투표와 소유자의 최종 확인으로 확정합니다. 동률·과반수 미달은 재투표합니다. 세 엔딩 모두 이후 공동 활동에 접근할 수 있습니다.

## 백업과 복구

```powershell
npm run backup:server
npm run backup:server -- server/data/worlds.sqlite server/data/manual-backup.sqlite
```

SQLite 백업 API로 일관된 복사본을 만들고 무결성을 검사합니다. 기존 대상 파일은 덮어쓰지 않습니다. 복구할 때는 서버를 종료하고 백업을 **새 파일**로 복사한 뒤 `COOP_DATABASE`를 변경해 다시 실행합니다. 실행 중인 DB와 WAL 파일을 따로 복사하거나 덮어쓰지 마세요.

DB 스키마는 v1이며 더 높은 버전은 시작 시 거부합니다. 자원 변경은 즉시, 일반 이동·상태는 최대 약 2초 간격으로 저장합니다. 비정상 종료 시 마지막 주기 저장 이후의 이동은 되돌아갈 수 있습니다. 소유자가 나가도 다른 접속자가 있으면 세계는 계속 진행됩니다.

## 네트워크와 운영 범위

현재 인증은 **개발 전용 게스트**입니다. `NODE_ENV=production`에서는 인증 제공자 미설정 오류로 서버가 시작되지 않습니다. 이를 우회한 공개 서버 운영 구성은 제공하지 않습니다. 유료 서버·외부 계정·DNS·실서비스 라우팅을 만들거나 변경하지 않았습니다.

신뢰하는 LAN의 다른 PC에서 시험하려면 서버 PC 주소로 `APP_ORIGIN`과 `VITE_COOP_ORIGIN`을 맞추고 `COOP_HOST=0.0.0.0`으로 실행합니다. Vite도 `npm run dev:client -- --host 0.0.0.0`으로 바인딩합니다. 브라우저의 정확한 출처가 `APP_ORIGIN` 허용 목록과 같아야 합니다. 방화벽과 접근 범위는 테스트 네트워크에 맞춰 설정해야 합니다. 실제 두 물리 PC나 인터넷 경로에서 검증했다는 뜻은 아닙니다.

배포용 클라이언트는 `VITE_COOP_ORIGIN`을 지정해 빌드합니다. 누락 시 온라인 설정 오류를 알리며 싱글플레이는 계속 사용할 수 있습니다. 정적 호스팅만으로 지속 WebSocket 서버와 SQLite 영속 볼륨을 운영할 수 없습니다. 공개 운영에는 별도 서버, HTTPS/WSS, 운영 인증·계정 복구, 모니터링·백업 운영, 원격 네트워크 검증이 필요합니다. 도메인을 소스에 넣지 않고 환경별 `APP_ORIGIN`, `VITE_COOP_ORIGIN`으로 지정합니다.

공개 로비·친구/DM·영구 계정 복구는 포함하지 않습니다. 새 캐릭터부터 모든 온라인 행성·던전·레이드까지의 장기 인간 플레이, 실인터넷 안정성, 다수 월드 동시 부하는 별도 검증이 필요합니다.
