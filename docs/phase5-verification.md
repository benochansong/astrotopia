# Phase 5 검증 기록 — BEYOND EDEN

## 구현과 기존 구조

Phaser Canvas 렌더러, TypeScript 물리·전투, 기존 생존/제작/연구 및 ColonySystem을 유지했습니다. SpaceSystem은 우주선 수리·항해·화물·행성별 로컬 상태를 관리합니다. 비활성 행성은 동일 산업 시스템을 임시 컨텍스트로 실행하고 화면·적 AI를 만들지 않습니다.

- 우주선 7개 시스템 복구, 기존 6개 납품/코어 분석 실적 인정
- 첫 이륙 20초, 반복 항해 8초/항법 강화 후 5초, 건너뛰기, 출발 시 연료 1회 차감, 중간 저장/재개
- 7개 행성 지도와 잠금 표시, 실제 EDEN↔ARES 왕복
- 선내 5개 구역, 회복, 수동 비상 연료 제작, 5종 장치 업그레이드
- ARES 4개 지역, 0.65G, 산소·열·모래폭풍·바람, 5종 탐험 장비
- 8종 생명체와 DUNE COLOSSUS 3단계/13개 공격 순서, 공격 예고, 코어 반격 창, 첫/반복 보상 분리
- ARES 원재료/정제/부품 및 5개 연구 노드, 퀘스트 29~38, 이륙 후 레벨 상한 30
- 독립 창고·생산 대기열·시설·채굴 쿨다운, 행성별 4시간 상한 오프라인 생산
- 기본 80/강화 160칸 화물, 인벤토리 및 현지 창고 양방향 원자적 이동, 검색, 원격 시설 가동 전환
- 기존 건설/전력/자동화에 방진·온도 조절·고효율 태양광·사막 채굴 시설 추가

## 저장 호환

기존 astrotopia.save.v1 키를 유지하며 스키마 버전은 5입니다. v1~v4 데이터를 순차 변환하고 이전 원본을 별도 백업합니다. 기존 플레이어 장비·자원·기지·연구·퀘스트를 보존합니다. 신규 행성 데이터는 방문 시 한 번만 생성합니다. 항해 대기 상태와 최초 착륙 지원 여부를 저장하여 재접속/건너뛰기 중복 지급을 차단합니다.

## 검증

- `npm run build`: TypeScript 검사 및 Vite 프로덕션 빌드 통과.
- `npm test`: 7개 파일, 94개 테스트 통과. 기존 캠페인 1~28과 신규 수리/연료/항해 재개/독립 창고/화물/원격 시뮬레이션/적 공격/보스 보상/열 보호 검증.
- `npm run test:e2e`: 실제 Chrome 10개 테스트 통과. 기존 전투·탐험·생존·기지 및 새 항해 UI 흐름 확인. 새 왕복 테스트에서 페이지 콘솔 예외 없음.
- `npm run test:production`: 결과는 아래 최종 기록 참조.
- 브라우저 항성계·내부·ARES 착륙/협곡·거신 화면 캡처를 `artifacts/phase5-*.png`에 보관.
- `artifacts/phase5-performance.json`: 제련소 전투 장면에서 5.001초 동안 실제 World.update 497회, 약 99.39 업데이트/초. 브라우저 rAF는 별도 측정이며 게임 FPS로 보고하지 않음. 이 환경의 짧은 측정이며 모든 PC의 성능을 보장하지 않음.

## 수정한 문제와 한계

항성계 창 너비와 자동 갱신에 따른 스크롤 초기화, ARES에서 기존 EDEN 포털/체크포인트 사용, 새 아이템으로 테스트 창고가 용량을 초과하는 문제를 수정했습니다. 기존 캠페인 테스트는 동시 빌드로 한 차례 5초 제한을 넘겼지만, 단독 전체 재실행에서 94개 모두 통과했습니다.

FROSTIA, 자동 화물 항로, 무작위 우주 항해 이벤트와 ODYSSEY/ARK는 이 버전에서 탐험 가능한 기능으로 표시하지 않습니다. FROSTIA는 이어지는 Phase 6의 첫 구현 대상입니다. 원격 관리는 가동/정지 수준이며 원격 건설/수리, 행성 간 자동 운송은 제공하지 않습니다. 장시간 메모리 누수 테스트와 모든 실장비의 성능 테스트는 실행하지 않았습니다.
