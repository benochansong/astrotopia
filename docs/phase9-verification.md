# Phase 9 검증 보고서

8단계 완료 커밋 `25e15d1`에서 `codex/phase-9-galactic-civilization` 브랜치를 만들었습니다. Phaser/TypeScript/Vite와 기존 게임 모듈을 유지했습니다. 8단계 기록은 `phase8-guide.md`, `phase8-verification.md`에 보존했습니다.

- 5종 계약을 창고별 1회 납품. 위조 코어·고유 보상 거래 불가.

- 식량·산소·가동 거주 구역·일자리·의료에 따른 집계 인구와 복지, 9직무 자동 배치와 우선 직무, 도시 6/7과 다중 행성 문명 8.

## 검증 결과

최종 소스의 단위 검사와 새 기능 브라우저 재검증을 완료했습니다.

- 단위·통합: **178/178 통과**, 12개 파일. 기존 161개와 신규 17개 시나리오.
- 개발 Chrome: **25/25 통과**. 세 경계 수정 후 새 기능 및 성능 **3/3 재검증 통과**.
- 프로덕션 Chrome: **7/7 통과**. 개발 훅 없이 저장 복원·시장·화물·정거장·기존 전직·건설·항해를 검증했습니다. 오프닝 표본 99.72 FPS / p95 14ms.
- 타입 검사·Vite 빌드 성공: 앱 JS 549.47 kB / gzip 193.18 kB, CSS 42.80 kB / gzip 10.42 kB, Phaser 1,208.06 kB / gzip 332.17 kB.
- 신규 브라우저 흐름은 실제 DOM 조작으로 시장 매입, 함선 건조, 항로 설정, 실시간 비행, 재접속과 목적지 하역, 정거장 이동/F 상호작용/귀환을 검증합니다. 프로덕션에서는 개발 훅에 의존하지 않습니다.
- 대규모 성능은 7행성·500건물·30함선·50항로·주민 5,000의 합성 저장 상태를 사용합니다. 건물 다수는 구조물이며 500개 동시 가동 공장의 최악 조건을 뜻하지 않습니다. 측정은 디스플레이 rAF가 아닌 실제 게임 업데이트 호출 간격으로 수행합니다.

## 발견하고 수정한 문제

1. 기존 저장 버전 기대값과 행성별 개별 비접속 테스트를 v9 단일 시계 구조에 맞췄습니다. 자원 보존 검사는 유지했습니다.
2. 비생산 건물에서도 모든 제작법을 반복 조회하던 경로를 조기에 종료해 기존 기지 캠페인과 비접속 처리 비용을 줄였습니다.
3. 대량 거래는 첫 단가에 전체 수량을 곱하지 않고 수량별 가격을 계산합니다. 자동 규칙은 주문의 마지막 한 개까지 가격 상·하한을 검사합니다.
4. 목적지 창고가 찬 화물선을 정비하면 유휴 상태로 바뀌던 문제를 발견했습니다. 적재 화물이 있으면 하역 대기를 유지하고 금지된 화물/상태 조합은 저장 검증에서 거부합니다.
5. 정거장에 ARES 과열과 FROSTIA 얼음 마찰이 남는 문제를 실내 환경 분기로 차단했습니다.
6. 테스트의 고정 시설 좌표가 일부 행성 스토리 보호 구역에 걸렸습니다. 성능 준비 시 실제 배치 검사로 가능한 위치를 고릅니다. 게임의 보호 구역 규칙은 유지했습니다.

## 확인 범위와 남은 제한

읽기 전용 생산 계획, 집계 도시·대표 주민, MK1/2 화물선, 정거장 1–3단계, 일반 자원 NPC 시장, 납품/국소 보호 기반 복원을 구현했습니다. 장비 시장, 연구/지원/개척선, 자동 공장 배치, 개별 5,000명 AI, 전면 테라포밍, 장편 문명 엔딩 영상은 포함하지 않습니다. 세 엔딩 모두 같은 기능에 접근하며 선택 기록을 변경하지 않습니다.

짧은 로컬 성능 표본은 모든 기기·장시간 운영·500개 공장 최대 생산 부하의 보장이 아닙니다. 새 게임부터 문명 8까지 전체 장기 인간 플레이와 경제 밸런스는 검증하지 않았습니다. 기본 물류/시장과 후반 기능은 자동 테스트용 진행 상태에서 실제 입력·차감·산출을 검증했습니다. 외부 온라인 서비스, DNS, 실제 결제는 추가하지 않았습니다.

실제 게임 업데이트 5.007초 표본: **98.26 FPS**, p95 **12.9ms**, 최대 **17.9ms**, 492회 업데이트. 결과: `artifacts/phase9-performance.json`. 관제·시장·항로·산업 계획·정거장·대규모 네트워크 스크린샷 6장을 직접 확인했습니다.
