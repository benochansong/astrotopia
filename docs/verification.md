# Phase 10 검증 보고서 · UNITED EXPLORERS

작성: 2026-11-27. Phase 9 완료 커밋 `650e6f1`에서 `codex/phase-10-united-explorers`로 이어 작업했습니다. **실행 가능한 비공개 2–4인 개발용 협동 클라이언트와 서버**를 구현했습니다. 인터넷 서비스 배포나 기획 전체의 최종 상용화를 완료했다는 의미는 아닙니다.

## 기존 프로젝트 분석과 보존

기존 프로젝트는 Phaser 3 / TypeScript / Vite 클라이언트이며 `World`에 이동·전투·행성·직업·개척·문명 시스템이 연결되어 있습니다. 싱글플레이의 v9 저장과 v1–8 변환, 일곱 행성, Lv.100, 여섯 직업, 고대 이야기·엔딩·문명 경제를 유지했습니다. Phase 9 기록은 [가이드](phase9-guide.md)와 [검증](phase9-verification.md)에 보존했습니다.

온라인을 별도 진입 모드로 분리했습니다. 온라인 중 싱글플레이의 시간 진행과 저장을 중단하고 기존 `astrotopia.save.v1`을 수정하지 않습니다. 온라인 캐릭터는 서버에서 새로 생성하며 로컬 저장의 레벨·아이템·화폐를 신뢰하지 않습니다. 기존 지형·이동 물리·적·무기 데이터와 개척/생산/문명 엔진을 공유하되, 네트워크 상태와 명령 판정은 서버가 소유합니다.

## 서버 구조와 저장 보호

Node.js 24.14+, `ws`, Node 내장 SQLite, TypeScript/`tsx`를 사용합니다. HTTP가 게스트 세션·월드 생성/참가·일회성 접속 티켓을 제공하고 WebSocket은 인증된 입력·명령·서버 상태를 전달합니다. 원본 세션 토큰 대신 해시를 저장하며 티켓은 15초/1회, 초대는 24시간 유효합니다. Origin 허용 목록, 입력 필드/수치 검사, 요청·메시지 속도 제한, 8KB 메시지 상한, 느린 연결 종료, 하트비트가 있습니다.

`Room → ColonyRoom → ExpeditionRoom`이 전투·경제·원정을 담당합니다. 각 월드는 독립된 상태를 갖습니다. 개인/공동 자원 변경과 요청 처리 영수증을 하나의 트랜잭션으로 저장합니다. 같은 요청 ID와 다른 내용은 거절하며 같은 요청의 재전송은 기존 결과만 반환합니다. 서버 재시작 때 남은 거래 제안은 한 번 반환합니다. 소유자가 나가도 다른 접속자는 계속 플레이할 수 있습니다.

SQLite WAL/FULL, 스키마 v1, 미래 스키마 거절, 원자 저장을 적용했습니다. 중요 자원 변경은 즉시, 이동 등 일반 상태는 약 2초 간격으로 저장합니다. 마지막 주기 저장 이후의 이동은 비정상 종료 때 되돌아갈 수 있습니다. 백업은 SQLite backup API와 전후 무결성 검사를 사용하고 기존 목적지를 덮어쓰지 않습니다. 복구는 종료된 서버에 새로운 DB 경로로 수행합니다. 비접속 경제는 기존 최대 4시간 처리와 단일 시계를 재사용합니다.

스냅샷은 관심 영역 전체 상태를 보내며 정교한 변경분 압축 프로토콜은 아직 아닙니다. 서버 전체 루프 시간에는 물리·경제·저장과 스냅샷 직렬화가 포함됩니다. 20Hz는 목표 주기이며 느린 기기에서 절대 보장하지 않습니다.

## 실행·초대·접속

[README](../README.md)의 실행/환경/백업 안내가 기준입니다.

```powershell
npm ci
Copy-Item .env.example .env
npm run dev:server
```

별도 터미널에서:

```powershell
npm run dev:client
```

`http://127.0.0.1:5180` → 협동 탐험 → 게스트 호출명 → 월드 생성 → 월드 L → 초대 복사. 다른 브라우저 프로필 또는 시크릿 창에서 새 게스트로 초대 코드를 입력합니다. 친구 관계를 등록하는 별도 소셜 서비스는 없으며 초대 링크로 함께 접속합니다. P에서 파티를 구성합니다. 서버 상태는 `http://127.0.0.1:5190/health`입니다.

`npm run backup:server`는 서버와 동일하게 `.env`/`.env.local`을 읽습니다. 저장소에 DB·토큰·실제 환경 파일을 커밋하지 않습니다.

**검증된 연결은 같은 PC의 독립 브라우저/프로세스 사이 실제 TCP/WebSocket입니다. 두 물리 PC나 인터넷 원격 접속은 검증하지 않았습니다.** 신뢰하는 LAN 설정 방법은 README에 있습니다. 공개 운영은 미배포이며 개발용 게스트 인증 때문에 `NODE_ENV=production` 서버 시작을 명시적으로 거부합니다. 정적 프로덕션 클라이언트에서 서버 설정/접속이 없을 때 싱글플레이를 계속할 수 있습니다. 영구 계정·계정 복구·HTTPS/WSS·영속 서버 운영과 모니터링은 후속 작업입니다. 유료 자원·DNS·실서비스 라우팅 변경은 하지 않았습니다.

## 자동화 검증

- 단위·통합 **193/193 통과**, 14개 파일: 기존 178개 + 온라인/복구 15개. `npm test -- --maxWorkers=2`.
- 기존 개발 브라우저: 전체 25개 실행에서 24개 통과, 새 협동 버튼으로 변경된 Tab 순서 검사 1개 실패. 새 버튼의 키보드 접근성도 확인하도록 기대 순서를 갱신한 뒤 해당 검사 **1/1 통과**. 최종 25개 시나리오의 통과를 확인했습니다.
- 최종 온라인 브라우저 결과: **2/2 통과**. 두 실제 브라우저의 초대·파티·이동·채팅·공동 전투·건설 권한·잠금·싱글 저장 보존과 네 실제 브라우저 동시 접속을 재검증했습니다.
- 프로덕션 브라우저 결과: **8/8 통과**. 개발 훅 없이 기존 이야기·직업·건설·화물·정거장·행성 이동·오프닝을 확인했고, 온라인 서버 부재 후 싱글 저장 보존과 계속하기도 통과했습니다. 기존 싱글 렌더 5초 표본은 99.04 FPS / p95 14.3ms였습니다.
- TypeScript 검사와 Vite 빌드 통과. 앱 JS **588.21 kB / gzip 206.66 kB**, CSS **46.78 / 11.28 kB**, Phaser **1,208.06 / 332.17 kB**.
- 실제 네트워크 프록시의 왕복 지연 20/50/100/200ms에서 이동과 입력 해제 검증. 각각 168px 이동, 전체 서버 루프 p95 약 **2.60 / 2.15 / 3.13 / 2.68ms**. 원시 결과: [지연 검사](../artifacts/phase10-network-latency.json).
- 최종 4브라우저 성능: **각 67.07–67.16 FPS**, 최근 최대 600프레임의 간격 p95 **20.7–21.4ms**, 로컬 왕복 **5–8ms**, 전체 서버 루프 p95 **4.76ms**. 같은 PC의 독립 Chrome 컨텍스트 4개, EDEN의 5초 동안 각 336회 실제 온라인 렌더를 측정했습니다. 화면 갱신용 rAF 빈도를 게임 FPS로 대신하지 않았습니다. 부하에 따라 직전 표본은 약 51 FPS였으며 60 FPS를 모든 환경에 보장하지 않습니다. [원시 결과](../artifacts/phase10-four-client-performance.json).

개발 회귀에는 오프닝·이동·채집·전투·기존 장비·생존·제작·연구·건설·자동화·전력·함선·일곱 행성·직업·궁극기·고대 이야기·최종 보스·엔딩·문명·운송·정거장·설정·저장 복원이 포함됩니다. 프로덕션 검사는 개발 훅 없이 기존 기능과 온라인 진입 실패 후 싱글 저장 보존을 확인합니다. 자동 검사가 재미, 장기 균형 또는 모든 인간 플레이 경로를 보장하지는 않습니다.

## 수정한 문제와 사용자 경험

- CRITICAL: 현재 행성에 원격 행성 전환용 컨텍스트를 중첩 적용하면 창고 배열이 이전 상태로 복구될 수 있었습니다. 현재 행성에서는 컨텍스트 전환을 생략하고 교차 행성 보존 검사로 확인했습니다.
- CRITICAL: 재접속 재전송, 거래 임시 보관, 가방 초과 보상, 강제 종료 복구에서 중복 지급/유실을 방지하도록 처리 기록·보류 보상·거래 반환을 연결했습니다.
- HIGH: 다른 행성 제작 대기열을 잘못 표시하는 경로, 인스턴스가 일반 부활 지점을 덮는 경로, 출발 행성에서 구할 수 없는 고정 연료로 귀환이 막히는 경로를 수정했습니다.
- HIGH: 권한 요청의 특수 객체 키, 중복 연구 비용, 지원 보상 자격, 연결 종료 후 방어/설치 효과, 서로 다른 장치를 한 명이 대신 작동하는 경로를 제한했습니다.
- MEDIUM: 4개 브라우저 동시 실행의 배경 재렌더 비용을 줄이기 위해 정적 배경을 캐시했습니다. 캐릭터·적·신호는 매 프레임 렌더링합니다. 미해금 원정의 잠금 이유, 온라인 오프라인 상태와 재시도를 표시합니다.
- LOW: 타이틀의 새 협동 버튼까지 키보드 Tab 순서 검사를 확장했습니다.

현재 자동 검사에서 재현된 저장 손상·자원 복제·서버 충돌·권한 우회 미해결 사례는 없습니다. 공개 운영 인증 미완성은 배포 차단 조건이며, 코드가 직접 시작을 거부합니다. 일반 사용자 관점에서는 초대·역할·각자 준비의 차이를 안내하지만, 개척/원정 메뉴의 정보량과 장기 성장 속도는 추가 사용자 평가가 필요합니다. 신규 캐릭터에서 전 레이드까지의 수동 완주나 재미 평가를 수행했다고 주장하지 않습니다.

## 이전 Phase에서 남은 범위

후속 단계에서 이미 구현된 행성 항해·OMEGA·엔딩·직업·문명·협동을 과거 문서의 미구현 목록에서 다시 미구현으로 세지 않습니다. 현재 남은 대표 범위는 다음과 같습니다.

- 개척: 중앙 창고 기반 생산이며 컨베이어/분배기 등 개별 물류망, 자유로운 지하 건축, 복잡한 문·사다리와 추가 침공 종류는 확장 영역입니다.
- 극한 환경: 완전한 수중 굴절 셰이더, 자유 깊이 건축, 독립 내열 로버/달 호버·다중 차고, 정밀 대기 시뮬레이션은 없습니다.
- 직업: 교관은 대화/초상 중심이며 독립 경로 탐색 NPC가 아닙니다. 직업 시험은 공유 훈련 지형과 목표를 사용합니다. 모든 기술별 신규 애니메이션과 장시간 동등 조건 DPS 균형 검증은 없습니다.
- 고대 콘텐츠: 고정 횡스크롤 던전, 순서 퍼즐, 지정 부유 구역입니다. 절차 미궁·완전한 천장 역중력·성우·전용 녹음 OST·기지 전체 몽타주는 없습니다.
- 문명: 일반 16품목 시장, MK1/2, 정거장 1–3단계, 집계 도시입니다. 장비 시장·연구/지원/개척선·자동 공장 배치·5,000명 개별 AI·전면 테라포밍·다른 항성계의 실제 플레이 맵은 없습니다.
- 전체: 신규 1–100 캐릭터에서 문명 8까지 장기 수동 완주, 모든 기기/난이도의 균형과 장시간 성능은 검증하지 않았습니다.

## Phase 10 제한과 우선순위

1. 운영 인증·계정 복구·장기 소유권 유지, HTTPS/WSS와 영속 서버 배포·백업 운영, 두 물리 PC/인터넷 지연·단절 테스트. 현재 게스트는 8시간이며 만료·로그아웃 후 계정 복구가 없습니다.
2. 새 온라인 캐릭터의 전 행성·장비·던전 성장 경로와 2/3/4인 장기 균형 검증. 온라인 장비 7단계·6직업 24기술은 별도 협동 구현이며 싱글플레이의 모든 장비 옵션/전직 트리/궁극기를 완전히 이식하지 않았습니다. 극한 환경은 행성 중력·슈트 기반 피해 중심이며 모든 싱글 환경 상호작용은 아닙니다.
3. 캠페인 보스의 고유 패턴 확장과 네 던전의 전용 지형/퍼즐/연출. 현재 캠페인 적은 공통 서버 AI를 활용하며 레이드만 별도 4단계 패턴을 가집니다. 레이드는 기존 적 아트를 사용합니다.
4. 원정·개척 메뉴 정리, 역할별 상세 권한 편집 UI, 접근성/리맵과 지원 역할의 사용자 평가. 세부 권한은 서버 프로토콜에 있고 UI는 역할 변경 중심입니다.
5. 변경분 스냅샷·서버 방 정리 정책·다수 월드 부하/장기 메모리/백업 보존·로그 운영 검증. 현재 짧은 로컬 표본으로 서비스 규모 안정성을 주장하지 않습니다.
6. 선택 기능인 공개 방 탐색·친구 목록·DM·플랫폼 로그인, 추가 전용 아트·사운드. 아직 구현하지 않았고 가짜 메뉴나 데이터로 제공하지 않습니다.
